# MIR Interpreter Bug Fix Session — 2026-04-02

This document summarises every correctness bug fixed, diagnostic improvement
added, and tooling built during this session while bringing the MIR interpreter
to full semantic parity with BSC's stock EVM interpreter.

---

## Background

Following the 2026-04-01 session (see `BUG_FIX_2026-04-01.md`), the MIR
interpreter had robust fallback infrastructure for CFG-level failures.  This
session focused on **semantic divergences** — cases where MIR successfully built
a CFG and ran to completion, but produced a different gas cost, execution
outcome, or state mutation than the stock EVM.  All five bugs below produced
BAD BLOCK consensus failures on BSC testnet, visible as "expected tx hash"
errors in the PoSA system-transaction hash.

## Bug 1 — SELFDESTRUCT missing 5000 base gas (EIP-150)

**Commit:** `443651a02`  
**File:** `core/opcodeCompiler/compiler/MIR/MIRInterpreter.go`  
**Affected block:** 7486959

### Root Cause

`chargeSelfdestructDynamicGas()` charged only the dynamic components of
SELFDESTRUCT (EIP-2929 cold-account access, EIP-150 create-by-selfdestruct).
It was missing `params.SelfdestructGasEIP150 = 5000`, the base cost introduced
in Tangerine Whistle.

In the stock EVM this 5000 appears in two places:
- **Pre-EIP2929:** as the first item in `gas_table.go:gasSelfdestruct`
- **Post-EIP2929:** moved to `constantGas` in `enable2929`; the dynamic function
  only covers extras

MIR has no `constantGas` split, so its dynamic function must cover all costs.

### Impact Chain

1. SELFDESTRUCT in tx 0 (contract `0x97b4CC…`) undercharged by 5000 gas
2. Refund cap (`gasUsed/2`) scales with `gasUsed` → net effective undercharge = **2500 gas**
3. At 30 gwei: 2500 × 30e9 = **75 T wei** less credited to SystemAddress
4. PoSA system reward tx used wrong value → "expected tx hash" BAD BLOCK

### Fix

```go
if it.chainRules.IsEIP150 {
    gas += params.SelfdestructGasEIP150  // 5000
}
```

Added as the first charge in `chargeSelfdestructDynamicGas()`, before the
EIP-2929 cold-access check.

## Bug 2 — Stack underflow silently executes with phantom operands

**Commits:** `41075b6e6`, `ea5a9bea0`  
**Files:** `ValueStack.go`, `opcodeParser.go`, `MIRInterpreter.go`  
**Affected block:** 9982725

### Root Cause

`ValueStack.pop()` returned `Value{kind: Unknown, liveInPos: -1}` when the
stack was empty, with no error.  The CFG parser would then build a block with
phantom SSA operands for instructions that would unconditionally stack-underflow
at runtime.

`evalValue()` in the interpreter handled `Unknown` values in the `default` case
by silently returning `u256Zero`.  So MIR executed the instruction with a ghost
zero operand, consumed only the instruction's base gas (e.g. 3 gas for CALL
overhead), and returned success — while the stock EVM correctly failed with
"stack underflow (0 <=> 2)" and consumed all gas.

**Concrete tx:** contract `0xA8b17417…`, first opcode requires 2 stack items
with nothing pushed.  MIR: 22031 gas used, status=success.  Stock: 2000000 gas
used (all gas), status=failure.  Fee delta: **~19.78 T wei**.

### Fix — Two-layer defence

**Layer 1 (parse-time, `41075b6e6`):** Add `underflowed bool` to `ValueStack`.
Set it in `pop()` on empty stack.  In `buildBasicBlock`'s main loop, after each
opcode dispatch, check:

```go
if stack.underflowed && c != nil && c.runtimeEpoch == 0 &&
    block.blockNum == 0 && len(block.parents) == 0 && initHeight == 0 {
    return fmt.Errorf("MIR CFG parse: stack underflow at pc=%d ...", ...)
}
```

Restricted to the true EVM entry block (no parents, empty entry stack) to avoid
false positives during iterative CFG fixpoint construction, where non-entry
blocks may temporarily have an empty entry stack on their first visit.

**Layer 2 (runtime, `ea5a9bea0`):** In `evalValue()`, the `default` case now
distinguishes `liveIn` status:

```go
default:
    if !v.liveIn {
        // Created by pop() on empty stack — unconditional underflow.
        return nil, fmt.Errorf("stack underflow (0 <=> 1)")
    }
    return u256Zero, nil  // legitimate live-in placeholder
```

`Unknown{liveIn: false}` is created **exclusively** by `pop()` on an empty
stack.  `Unknown{liveIn: true}` is created by `padBottomTo()` (DUP/SWAP
padding) and PHI slot construction — both legitimate.  The runtime error causes
`finishResult` to set `gasUsed = gasLimit`, exactly matching stock EVM.

## Bug 3 — EIP-6780 SELFDESTRUCT not implemented (Cancun+)

**Commit:** `b37e6b101`  
**Files:** `state_backend.go`, `statedb_backend.go`, `MIRInterpreter.go`

### Root Cause

`execSelfdestruct()` always called `StateDB.SelfDestruct()`, which unconditionally
marks the contract as self-destructed and zeroes its balance.  On Cancun+
networks (`IsCancun = true`, active on BSC testnet), the stock EVM uses
`opSelfdestruct6780()` → `StateDB.SelfDestruct6780()`, which only actually
destructs the contract if it was created **in the current transaction**
(`stateObject.newContract == true`).  For pre-existing contracts it only
transfers the balance.

Erroneously destroying pre-existing contracts clears their storage and code,
causing divergent state roots.

### Fix

1. Added `SelfDestruct6780(addr common.Address) bool` to the `StateBackend`
   interface.
2. `StateDBBackend` delegates to `db.SelfDestruct6780()`.
3. `InMemoryState` (test-only) always destructs (no transaction context).
4. `execSelfdestruct()` branches on `chainRules.IsCancun`:

```go
if it.chainRules.IsCancun {
    it.state.SubBalanceU256(it.contractAddr, bal)
    it.state.AddBalanceU256(beneficiary, bal)
    it.state.SelfDestruct6780(it.contractAddr)
} else {
    it.state.AddBalanceU256(beneficiary, bal)
    it.state.SetBalanceU256(it.contractAddr, u256Zero)
    it.state.SelfDestruct(it.contractAddr)
}
```

The Cancun path uses `SubBalance + AddBalance` to match `opSelfdestruct6780`'s
balance-tracing behaviour exactly.

## Bug 4 — CALL with oversized gas argument returns error instead of capping

**Commit:** `7ff725cc4`  
**File:** `core/opcodeCompiler/compiler/MIR/MIRInterpreter.go`  
**Affected block:** 10467963

### Root Cause

MIR's call gas calculation checked `!gasReq.IsUint64()` and returned
`errors.New("call gas overflow")` if the CALL opcode's gas argument did not fit
in uint64 (e.g. `gas = MaxUint64` pushed on the stack, a common "give me all
gas" idiom).  This aborted the call and consumed all caller gas.

The stock EVM's `callGas()` (`core/vm/gas.go:38`) handles this case by capping
to the EIP-150 63/64 limit:

```go
if !callCost.IsUint64() || gas < callCost.Uint64() {
    return gas, nil   // cap to 63/64 of available
}
```

A gas request that doesn't fit in uint64 is trivially larger than 63/64 of any
realistic gas budget, so capping is always the correct action.

### Impact

tx idx=8, block 10467963: MIR failed with "call gas overflow", used 42552 gas,
status=failure.  Stock EVM succeeded, used 42331 gas, made a nested CALL with
`gasIn=18940`.  Fee difference: **~2.21 T wei**.

### Fix

```go
avail := it.gasLeft()
if it.chainRules.IsEIP150 {
    avail = avail - avail/64
}
var gasToSend uint64
if gasReq == nil || !gasReq.IsUint64() || gasReq.Uint64() > avail {
    gasToSend = avail   // cap — mirrors callGas()
} else {
    gasToSend = gasReq.Uint64()
}
```

## Diagnostic / Observability Improvements

### Fallback logging (`2cc1ed250`)

Every `EVMRunner.Run()` fallback path now emits a structured log entry so
fallback frequency and reasons are visible without `MIR_DEBUG_LOG=1`:

| Trigger | Level | Fields |
|---------|-------|--------|
| `gas == 0` | Debug | addr, codeLen |
| `code > 2048` (pre-CFG) | Debug | addr, codeLen |
| CFG parse failed | **Warn** | addr, codeHash, codeLen, err |
| `needsRuntimeEpoch` / `code > 2048` (post-CFG) | Debug | addr, codeHash, codeLen, needsRuntimeEpoch |
| Unresolved jumps | Debug | addr, codeHash, codeLen |

CFG parse failures are `Warn` because they indicate MIR infrastructure failures
that warrant attention.

## Tooling: MIR Benchmark Mode (`fb54dffbe`)

**Files:** `vm/interpreter.go`, `vm/mir_runner.go`,
`core/opcodeCompiler/compiler/MIR/evm_runner.go`,
`core/state_processor_mir_bench.go`, `core/state_processor.go`

### Design

Added `vm.Config.MIRBenchmark bool`. When both `EnableMIR` and `MIRBenchmark`
are set, each transaction is executed up to three times per block:

1. **MIR timing run** — full execution via MIR, state reverted after
2. **Stock timing run** — full execution via stock EVM, state reverted after
   *(only when MIR ran without fallback)*
3. **Real run** — authoritative execution, state kept, receipt returned

If MIR fell back to a fallback interpreter, only steps 1 and 3 are run (the
fallback is already the stock interpreter, so a second timing run is redundant).

### Infrastructure

- `EVMRunner.fellBack bool` — reset at the top of each `Run()`, set at every
  fallback branch, exposed via `FellBack() bool`
- `EVM.GetMIRRunner() ContractRunner` — allows callers to type-assert to
  `*mir.EVMRunner` to call `FellBack()`
- `mirBenchmarkTx()` — orchestrates the three-run protocol using
  `statedb.Snapshot()/RevertToSnapshot()` and independent `GasPool` copies
- `mirBenchLogBlock()` — logs block-level aggregate after the tx loop

### Output

```
INFO  MIR bench tx  block=10467963 txIdx=3 txHash=0xabc… mir_ns=12450 base_ns=18900 speedup_pct=34.13
INFO  MIR bench tx (fallback)  block=10467963 txIdx=6 txHash=0xdef… mir_ns=180000
INFO  MIR bench block summary  block=10467963 benchmarked_txs=9 fallback_txs=2 \
      total_mir_ns=142000 total_base_ns=201000 block_speedup_pct=29.35
```

Zero overhead when `MIRBenchmark = false`.  **Must not be enabled in production**
as it triples execution cost for benchmarked transactions.

## Systematic Audit Results

A full semantic audit of MIR vs stock EVM was performed covering: EXP, SLOAD,
SSTORE, EXTCODE\*, BALANCE, CALL/CALLCODE/DELEGATECALL/STATICCALL (stipend,
new-account gas, 63/64 rule), CREATE/CREATE2, LOG0-4, KECCAK256, all COPY
opcodes, memory expansion formula, RETURNDATACOPY, and error gas semantics.

**No additional divergences were found** beyond the four bugs fixed above.
All complex gas rules (EIP-2200/2929/3529, call stipend, 63/64 cap, quadratic
memory expansion) are correctly implemented in MIR.

## Key Invariants Reinforced

> **Unknown SSA values with `liveIn == false` always represent EVM stack
> underflows.  They must never be silently treated as zero — they must trigger
> a fatal error that consumes all gas, matching the stock EVM.**

> **CALL gas arguments that exceed uint64 are not errors — they are requests
> larger than the 63/64 cap and must be silently capped, never rejected.**

> **On Cancun+, SELFDESTRUCT only destroys a contract if it was created in the
> current transaction.  For pre-existing contracts it is a balance transfer only.**
