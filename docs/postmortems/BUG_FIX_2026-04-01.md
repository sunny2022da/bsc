# MIR Interpreter Bug Fix Session — 2026-04-01

This document summarises every correctness bug fixed and diagnostic infrastructure
added during this session while bringing the MIR (Mid-level IR) interpreter to
full parity with BSC's stock EVM interpreter.

---

## Background

MIR is an alternative EVM execution path in this BSC fork.  The `EVMRunner`
adapter (`core/opcodeCompiler/compiler/MIR/evm_runner.go`) compiles EVM bytecode
to MIR via a Control Flow Graph (CFG) built by `opcodeParser.go`, then executes
it with `MIRInterpreter`.  Any divergence between MIR and the stock `EVMInterpreter`
results in a wrong receipt root hash, a wrong gas balance on `consensus.SystemAddress`,
and ultimately PoSA system-transaction hash mismatches — all manifesting as
**BAD BLOCK** consensus failures.

---

## Bug 1 — `contract.Gas == 0` triggers "unlimited gas" in MIR

**Commit:** `adbb79607` / `060524660`  
**File:** `core/opcodeCompiler/compiler/MIR/evm_runner.go`

### Root Cause

`MIRInterpreter.gasLeft()` returns `MaxUint64` when `gasLimit == 0`, treating
zero as "unlimited" — a testing/tool mode.  When a transaction's gas limit
exactly equals its intrinsic gas cost the EVM enters the call with
`contract.Gas == 0`.  MIR interpreted that as unlimited gas and executed the
call without any gas restriction, while the stock interpreter consumed the first
opcode and immediately returned `ErrOutOfGas`.

**Concrete block:** 2737530 — `intrinsicGas == gasLimit == 87272` →
`gasAfterIntrinsic == 0`.  MIR gave a `CREATE2` call `18158513697557839872` gas
units; stock EVM gave it `0` and returned OOG.

### Why "just return OOG" is wrong

The stock EVM does **not** check gas at call entry — it checks at the first opcode
cost deduction.  A contract whose first opcode is `STOP` would succeed with
`gas == 0` in stock EVM.  Returning `ErrOutOfGas` directly from MIR would
diverge for that case.

### Fix

When `contract.Gas == 0`, delegate immediately to `baseIt` (a lazily-created
`EVMInterpreter` instance on the runner):

```go
if contract.Gas == 0 {
    if r.baseIt == nil {
        r.baseIt = vm.NewEVMInterpreter(r.evm)
    }
    return r.baseIt.Run(contract, input, readOnly)
}
```

This guarantees complete semantic parity for the zero-gas edge case.

## Bug 2 — CFG parse failure propagates as execution error (wrong gas consumed)

**Commit:** `10a36079f`  
**File:** `core/opcodeCompiler/compiler/MIR/evm_runner.go`

### Root Cause

`getOrBuildCFGEntry` returns a `CFGNonConvergentError` when `CFG.Parse()` fails
to reach a fixpoint.  The error bubbled up through `EVMRunner.Run` to
`evm.Call`, which treated it as an execution failure and set `contract.Gas = 0`
(consuming all remaining gas).  The wrongly-consumed gas was credited to
`consensus.SystemAddress` as a block fee, changing the system address balance
and invalidating the PoSA system transaction value — causing an "expected tx
hash" BAD BLOCK error at block 3073916.

### Fix

On any CFG infrastructure error, fall back to `baseIt` instead of propagating:

```go
e, err := getOrBuildCFGEntry(codeHash, contract.Code)
if err != nil {
    log.Error("MIR CFG parse failed, falling back to base interpreter", ...)
    if r.baseIt == nil {
        r.baseIt = vm.NewEVMInterpreter(r.evm)
    }
    return r.baseIt.Run(contract, input, readOnly)
}
```

## Bug 3 — CFG fixpoint algorithm does not converge for pre-Solidity-0.5 contracts

**Commit:** `96204ee1f`  
**File:** `core/opcodeCompiler/compiler/MIR/opcodeParser.go`

### Root Cause

Pre-Solidity-0.5 compilers implement internal function calls by pushing a return
address on the stack and using a dynamic `JUMP` at the end of the function body.
When the same function is called from multiple sites, the return address is a
`MirPHI` node merging all callers' addresses.

Combined with for-loops (loop back-edges), this creates a circular dependency:

1. The **loop entry block** builds its PHI values from incoming snapshots,
   including the return-address PHI.
2. The **dynamic JUMP block** (function return) resolves its target by tracing
   the PHI def-chain through predecessors.
3. When any predecessor's exit snapshot changes, `connectEdge` calls
   `markDescendantsForRebuild`, invalidating all descendants — including the
   loop entry block.
4. Rebuilding the loop entry block changes its PHI values, invalidating the
   dynamic JUMP block.
5. → back to step 2, oscillating indefinitely.

**Concrete contract:** `0x06ADe320c034E3770D9D99a19cEc42bF5c3FDc83`  
(codeHash `0x0d18b588...`, 1780 bytes, 42 JUMPDESTs, 41 JUMPs).  
Dynamic return JUMPs at PCs `0x300`, `0x308`, `0x5af`, `0x6c7`.  
Loop back-edges at PCs `0x18e`, `0x315`, `0x468`, `0x5b8`.  
The algorithm ran **114,945 block builds** before hitting the global `maxBuilds`
limit (`1024 + 64 × 1780 = 114,944`).

### Fix

Add a **per-block rebuild counter** alongside the existing global counter.
A non-convergent CFG manifests as a small set of blocks oscillating thousands
of times, not as every block being built many times.  Detecting the first
block that exceeds 64 rebuilds catches the pathology ~36× faster:

```go
const maxBuildsPerBlock = 64
blockBuilds := make(map[*MIRBasicBlock]int, len(c.basicBlocks)+16)

// inside the worklist loop:
blockBuilds[block]++
if builds > maxBuilds || blockBuilds[block] > maxBuildsPerBlock {
    return &CFGNonConvergentError{...}
}
```

**Threshold rationale:** A correctly-converging CFG never needs more than ~10
rebuilds per block (a few iterations to stabilise multi-predecessor PHIs).
64 gives 6× headroom.  A non-convergent CFG would need thousands of rebuilds
per block, so the threshold fires well before the global limit.

The `baseIt` fallback from Bug 2 then handles execution for the affected contract
with full semantic parity.

## Key Invariant Established

> **All MIR execution paths must produce results identical to the stock
> `EVMInterpreter`.  Any MIR infrastructure failure (CFG build error, gas
> edge case) must fall back to `baseIt` — never propagate as an execution
> error that consumes gas or changes state differently from stock EVM.**
