# MIR Optimization Daily Summary (2026-04-03 ~ 2026-04-09)

## Overview

Major multi-day debugging and feature development session on the MIR (Mid-level IR) SSA-based EVM execution engine for BSC geth. Covered three main areas: bloom mismatch fix, depth restriction removal, and needsRuntimeEpoch fallback elimination.

---

## Phase 1: Bloom Mismatch Fix (Block 25070310)

### Problem
BAD BLOCK error on block 25070310 — MIR's computed bloom was a strict subset of stock EVM's bloom (7 bits missing).

### Root Cause
`chargeMemoryExpansion` checked offset overflow **before** checking size==0. When a contract passes `offset=MAX_UINT256, size=0`, stock EVM returns immediately (no expansion needed), but MIR returned `"memory offset overflow"` as an execution error. This caused the caller to revert state changes that stock EVM would keep.

### Fix
- Moved `size.IsZero()` check to the top of `chargeMemoryExpansion`, matching stock EVM's `calcMemSize64WithUint`
- Changed all remaining overflow paths to consume all gas (OOG) instead of returning execution errors
- Applied same fix to call memory offset/size overflow paths

### Key Commits
- `37f2f8cc0` — fix: match stock EVM memory overflow semantics

## Phase 2: Depth Restriction Removal

### Problem
MIR only executed at `depth==0` (top-level calls). All nested calls went through stock EVM, limiting MIR's coverage.

### Changes
1. **readOnly support**: Added `readOnly` field to MIRInterpreter with guards on SSTORE, TSTORE, LOG, CREATE, SELFDESTRUCT, and CALL-with-value
2. **Re-entrant interpreter management**: Each `Run()` takes/releases interpreter from pool, preventing nested calls from corrupting outer frame state
3. **readOnly propagation**: `runWithRunner()` now sets `evm.readOnly` mirroring stock interpreter
4. **MIR dispatch in all call types**: Added to StaticCall, CallCode, DelegateCall with correct contract semantics
5. **Empty code check**: Added `len(code)==0` early return for all new dispatch paths

### Bugs Found & Fixed
- **Double depth increment** (`f59a671aa`): `runWithRunner()` + `baseIt.Run()` both incremented depth. Moved depth management to `EVMRunner.Run()` via `IncDepth()/DecDepth()`.
- **Shared blockPos** (`096cb01dd`): `MIRBasicBlock.pos` was shared across re-entrant calls (proxy A calls A). Replaced with local `blockPos` variable — eliminated 33-gas divergence.
- **Empty code dispatch** (`96a6e6104`): MIR dispatched to CFG cache for addresses with no code, executing stale entries. Added `len(code)==0` guard.

### Key Commits
- `0928a58e5` — feat: remove depth==0 restriction
- `f59a671aa` — fix: eliminate double depth increment
- `096cb01dd` — fix: use local blockPos instead of shared MIRBasicBlock.pos
- `96a6e6104` — fix: skip MIR dispatch for empty code

## Phase 3: needsRuntimeEpoch Fallback Elimination

### Problem
78% of all MIR attempts fell back to stock interpreter due to `needsRuntimeEpoch` — triggered when merge points had incoming stacks of different heights.

### Investigation & Fixes

#### 3.1 Height Mismatch Analysis
- 100% of `needsRuntimeEpoch` triggers were `height_mismatch(0_vs_1)` — common in Solidity function dispatchers where multiple entry points merge into shared error/revert handlers
- Attempted to simply remove the guard → exposed deeper bugs in PHI evaluation

#### 3.2 PHI Stack-Top Alignment (`22d602a60`)
**Problem**: PHI operands were extracted from stack **bottom** (index `s[i]`), causing position 0 in a short stack to map to a different value than position 0 in a tall stack.

**Fix**: Use `idx = len(s)-1-distFromTop` to align from stack top. Parents whose stacks are too short for a given depth get Unknown (correct: those are unreachable "dead" bottom slots).

#### 3.3 Rebuild Thrashing (`4f90a3c7d`, `a8cfcaeca`)
**Problem**: When incoming stack height != entry stack height, `needSeed=true` triggered full block rebuild. With globally cached CFGs, this thrashed: height=1 rebuilds, then height=3 rebuilds back, each invalidating downstream PHI references → "missing result for def" errors.

**Fix**: Removed height-mismatch as a rebuild trigger in both `es!=nil` and `es==nil` paths. PHIs built at mode height handle shorter-stack edges via evalPhi's snapshot fallback.

#### 3.4 Graceful PHI Fallback (`4f90a3c7d`)
**Problem**: evalPhi/evalValue returned fatal errors for unresolvable PHI defs (stale references after rebuild).

**Fix**:
- `evalPhi`: returns `u256Zero` when all resolution paths exhausted (instead of fatal error)
- `evalValue`: PHI defs with missing results return `u256Zero` (non-PHI defs still error)

#### 3.5 Back-Edge Snapshot Materialization (`011b26075`)
**Problem**: `computeExitSnapshotForEdgeTo` materialized loop back-edge values into constants for static CFGs. This froze loop-carried values → rebuild saw identical constants from all parents → eliminated PHI → loop variable became constant → JUMPI cond=K(1) → infinite loop → OOG.

**Fix**: Loop back-edges (`to.firstPC <= from.firstPC`) now always return raw symbolic snapshot, regardless of CFG dynamism.

#### 3.6 Force PHI at Loop Headers (`7dff24e50`)
**Problem**: Parse-time CFG construction only traverses loop body once. All incoming snapshots at loop header carry same initial-iteration values. The `same` check eliminated PHI nodes, baking loop variables as constants at parse-time (not just runtime).

**Fix**: Detect loop headers (blocks with at least one back-edge parent where `parent.firstPC >= block.firstPC`) and skip the `same` check, unconditionally creating PHI nodes for every stack position. Runtime evalPhi selects the correct value per predecessor.

### Key Commits
- `22d602a60` — fix: PHI stack-top alignment for height-mismatched parents
- `4f90a3c7d` — fix: stop rebuild thrashing + graceful PHI fallback
- `a8cfcaeca` — fix: also disable height-mismatch rebuild in es==nil path
- `011b26075` — fix: never materialize loop back-edge snapshots to constants
- `7dff24e50` — fix: force PHI creation at loop headers

## Instrumentation Added

| Feature | Env Variable | Description |
|---------|-------------|-------------|
| Debug block | `MIR_DEBUG_BLOCK=N` | Per-opcode logging for specific block |
| Step trace | `MIR_STEP_TRACE=1` | Per-opcode gas capture in dual-exec mode |
| Force base | `MIR_FORCE_BASE=1` | Bypass all MIR execution |
| Disable from | `MIR_DISABLE_FROM=N` | Disable MIR for blocks >= N |
| Skip addr | `MIR_SKIP_ADDR=0x...` | Force baseIt for specific address |
| Halt after | `MIR_HALT_AFTER_BLOCK=1` | Exit after debug block completes |
| Debug log | `MIR_DEBUG_LOG=1` | Verbose MIR runner logging |

### Diagnostic Features
- **Dual-exec comparison**: MIR vs baseIt side-by-side with gas/error/returnData/refund diff
- **Calltree comparison**: Per-call gas/error diff between MIR and stock EVM
- **CFG dump on mismatch**: Full block structure with PHI operands and children
- **SLOAD/JUMPI tracing**: Slot values and branch decisions for control-flow diagnosis
- **Fallback reason counters**: `fb_gasZero`, `fb_cfgFail`, `fb_rtEpoch`, `fb_dynJump`
- **doCall gas checkpoints**: Entry, memExpansion, accessDelta, gasToSend, return
